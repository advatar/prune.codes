# CR-004 — Persistent Project Memory for Codex + OpenCode (Cortex‑Inspired)

## Summary
Add a **local, persistent “project memory” layer** to Prune that works **primarily with Codex and OpenCode** via MCP.

This CR introduces:

1. **Prune Memory** (built-in): a small local database of high-value decisions, patterns, and workflows.
2. **MCP tools** exposed by Prune so any client agent (Codex / OpenCode) can:
   - recall relevant memories at task start
   - remember new decisions during/after work
   - optionally “save session” summaries for long tasks
3. **Integration presets** for Codex + OpenCode (no forks):
   - Codex: `config.toml` MCP server entry + `AGENTS.md` guidance
   - OpenCode: `opencode.json` MCP server entry + optional plugin scaffolding
4. (Optional) **Compatibility mode**: allow using Cortex as an external memory MCP server instead of Prune Memory (two-server setup).

> Motivation: memory reduces “re-explaining” and stabilizes decisions across tasks. Combined with Prune’s code-context packs, this enables smaller models to perform reliably.

---

## Goals
- **Local-first** persistence (no cloud required).
- **Agent-agnostic**: memory tools live in Prune MCP, not inside a specific agent product.
- **Codex + OpenCode first** (Claude is not the primary target in this CR).
- **Hybrid retrieval** to support both short and long memories:
  - keyword (FTS) + embeddings + recency weighting
- **Strict budget controls** (memory recall should not flood the pack).

---

## Non-goals
- Replacing Prune’s code indexing or packer.
- Building a full transcript parser with complex heuristics in v1 (we can start with explicit `remember` + lightweight `save_session`).
- Server-to-server MCP bridging (agents call tools; Prune does not call other MCP servers).

## Architecture

### New crate
`crates/ce-memory/` (Rust)

Responsibilities:
- SQLite schema migrations
- insert/update/delete
- embedding computation (reuse existing embedder if available)
- hybrid search (FTS + cosine similarity)
- ranking (RRF + recency decay)

### Data model (SQLite)
Table `memories` (minimal v1):
- `id` INTEGER PK
- `project_id` TEXT NULL
- `content` TEXT NOT NULL
- `content_hash` TEXT UNIQUE (dedupe)
- `tags` TEXT NULL (comma-separated or JSON)
- `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
- `source` TEXT NULL (e.g. “explicit”, “session_save”)
- `embedding` BLOB NULL (float32[dims])  *(optional if embeddings enabled)*

FTS5 virtual table:
- `memories_fts(content, tags, content='memories', content_rowid='id')`

Indexes:
- `idx_memories_project_id`, `idx_memories_created_at`, `idx_memories_hash`

### Retrieval ranking
Compute 2 ranked lists:
- FTS list (BM25)
- Vector list (cosine similarity)

Fuse with **Reciprocal Rank Fusion**:
- score = Σ 1/(rrf_k + rank_i)

Apply **recency decay**:
- weight = 0.5^(age_days / half_life_days)

Final score:
- fused_score * recency_weight

## Codex integration (primary)

### Why this works
- Codex supports MCP servers via `~/.codex/config.toml` or `.codex/config.toml`.  
- Codex loads `AGENTS.md` before doing work, so we can teach it how to use Prune packs + memory tools.

### Changes required in Prune
Add a new integration preset:
- `ce integrate codex --preset prune-memory`

It writes/updates:
- `AGENTS.md` (or appends a Prune block)
- `.codex/config.toml` (project-scoped) with a local MCP server entry for Prune

**Example snippet (project-scoped `.codex/config.toml`)**
```toml
[mcp_servers.prune]
command = "ce"
args = ["mcp", "serve"]
cwd = "."
startup_timeout_sec = 20
tool_timeout_sec = 60
enabled = true
```

**AGENTS.md block (conceptual)**
- On task start: call `memory.recall` with the task intent and current area.
- Before edits: call `repo.ensure_fresh`, then `ce.pack`.
- After finishing: call `memory.remember` for decisions that should persist.

## OpenCode integration (primary)

### Why this works
OpenCode supports MCP servers in `opencode.json` under the `mcp` key, including local servers started by a command. OpenCode plugins can also react to session/tool events (optional automation).

### Changes required in Prune
Add integration preset:
- `ce integrate opencode --preset prune-memory`

It writes/updates:
- `.opencode/opencode.json` with the local MCP server entry for Prune
- `.opencode/plugins/prune_memory_autosave.ts` (optional; see below)

**Example `.opencode/opencode.json` snippet**
```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "prune": {
      "type": "local",
      "command": ["ce", "mcp", "serve"],
      "enabled": true,
      "timeout": 20000
    }
  }
}
```

### Optional plugin (automation)
Add a plugin scaffold that:
- On `session.created`: emits a short “run memory recall” hint (or automatically calls the tool via client API if supported).
- On `session.compacted` / `session.idle`: prompts to remember key decisions.
- On `tool.execute.after` for edits: adds a lightweight “changed files list” memory (optional).

> Keep this optional because “auto-memory” can become noisy. Default should be manual `remember` with strong guidance.

## Compatibility mode: external Cortex server (optional)
Because Cortex exposes an MCP server entry point (`dist/mcp-server.js`), advanced users can run it alongside Prune and configure both MCP servers in Codex/OpenCode.

Add a helper:
- `ce integrate memory --provider cortex`
which:
- prints the exact Codex/OpenCode config blocks for adding Cortex as a second MCP server
- (optionally) checks that `node` is installed and that the `dist/mcp-server.js` path exists

This is optional; the primary direction is **Prune Memory built-in**.

## Implementation details (code skeleton)

### 1) New crate layout
```
crates/ce-memory/
  Cargo.toml
  src/
    lib.rs
    db.rs
    schema.sql
    embed.rs
    search.rs
    rrf.rs
    recency.rs
    mcp_tools.rs
```

### 2) `schema.sql` (minimal)
```sql
CREATE TABLE IF NOT EXISTS memories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id TEXT,
  content TEXT NOT NULL,
  content_hash TEXT NOT NULL UNIQUE,
  tags TEXT,
  source TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  embedding BLOB
);

CREATE INDEX IF NOT EXISTS idx_memories_project_id ON memories(project_id);
CREATE INDEX IF NOT EXISTS idx_memories_created_at ON memories(created_at);

-- FTS5 (if available)
CREATE VIRTUAL TABLE IF NOT EXISTS memories_fts USING fts5(
  content,
  tags,
  content='memories',
  content_rowid='id'
);
```

### 3) MCP tool registration
In the existing MCP server crate:
- add `memory.*` tools to `tools/list`
- add handlers that call into `ce-memory`
