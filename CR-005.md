# CR-005 — Cortex External Provider Mode (Two MCP Servers) for Codex + OpenCode

## Summary
Add an **external memory provider mode** where Prune remains the repo-aware **context engine**, and **Cortex** runs as a **separate MCP server** that provides persistent memory tools.

This CR is **Codex + OpenCode first** and delivers:

1) A `ce integrate ... --with cortex` preset for **Codex** and **OpenCode** that configures **two MCP servers**:
   - `prune` (this repo context engine)
   - `cortex` (persistent memory MCP server)

2) A lightweight “vendor” installer that fetches/builds Cortex (without forking it), so the integration is reproducible and lives neatly under the Prune repo.

3) Updated agent instructions that make Codex/OpenCode reliably:
   - recall memory before acting
   - pack repo context before edits
   - remember decisions after changes

> Cortex is a separate OSS project with an MCP server entrypoint (`dist/mcp-server.js`) and tools like `cortex_recall`, `cortex_remember`, etc. The Cortex README shows `mcp-server.ts` and a built output `dist/mcp-server.js`, plus a manual `tools/list` test command. citeturn4view2

---

## Goals
- **No fork**: keep Cortex external; Prune just vendors/builds it.
- **Two MCP servers** configured automatically for Codex/OpenCode.
- **Idempotent integration**: re-running the integration updates safely without clobbering user settings.
- **Local-first memory**: Cortex keeps its DB under `~/.cortex/memory.db` by default. citeturn2view0
- **Simple to debug**: `ce cortex doctor` verifies Node, build output, and MCP readiness.

---

## Non-goals
- Not re-implementing Cortex inside Prune (that is CR-004).
- Not integrating Claude Code plugin/hook lifecycle.
- Not requiring a remote MCP server; Cortex runs locally as STDIO.

## Implementation details

### A) Vendor install/build of Cortex

#### A1) Clone Cortex into repo-local vendor dir
Target:
- `.prune/vendors/cortex/`

Use:
- `git clone https://github.com/hjertefolger/cortex .prune/vendors/cortex`

Optionally support pinning:
- `--ref v2.1.2` (example release tag; do not hardcode)

#### A2) Build the MCP server
In `.prune/vendors/cortex`:

```bash
npm install
npm run build:mcp
```

Cortex’s README lists:
- `npm run build:mcp` (build MCP server only)
- `dist/mcp-server.js` output citeturn4view2

#### A3) Validate the MCP server entrypoint
From inside `.prune/vendors/cortex`:

```bash
echo '{"jsonrpc":"2.0","method":"tools/list","id":1}' | node dist/mcp-server.js
```

This exact manual test is shown in Cortex’s README. citeturn4view2

### B) Codex integration (two MCP servers)

Codex supports MCP servers via `~/.codex/config.toml` or project-scoped `.codex/config.toml` (trusted projects), using `[mcp_servers.<name>]` tables. citeturn2view1

#### B1) Project-scoped `.codex/config.toml` snippet
Add or patch (idempotently):

```toml
[mcp_servers.prune]
command = "ce"
args = ["mcp", "serve"]
cwd = "."
enabled = true
startup_timeout_sec = 20
tool_timeout_sec = 60

[mcp_servers.cortex]
command = "node"
args = ["dist/mcp-server.js"]
cwd = ".prune/vendors/cortex"
enabled = true
startup_timeout_sec = 60
tool_timeout_sec = 120
```

Notes:
- Codex `command`, `args`, `cwd`, `enabled`, and timeouts are supported for STDIO MCP servers. citeturn2view1

#### B2) Optional: CLI method (alternative)
Codex also supports adding servers via CLI:

```bash
codex mcp add cortex -- node /ABS/PATH/TO/.prune/vendors/cortex/dist/mcp-server.js
```

CLI `codex mcp add <name> -- <stdio command>` is documented. citeturn2view1

### C) OpenCode integration (two MCP servers)

OpenCode supports local MCP servers in `opencode.json(c)` under `mcp` with:
- `type: "local"`
- `command: [ ... ]`
- `environment`
- `timeout` citeturn3view0

#### C1) Patch `.opencode/opencode.jsonc`
Add or patch:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "prune": {
      "type": "local",
      "command": ["ce", "mcp", "serve"],
      "enabled": true,
      "timeout": 20000
    },
    "cortex": {
      "type": "local",
      "command": ["node", ".prune/vendors/cortex/dist/mcp-server.js"],
      "enabled": true,
      "timeout": 20000
    }
  }
}
```

Notes:
- OpenCode supports local MCP servers and `command` arrays exactly as above. citeturn3view0
- This assumes OpenCode runs commands with the repo root as working directory (typical). If not, see “C2 wrapper script”.

#### C2) Robust wrapper script (recommended)
To avoid any working-directory uncertainty, generate:

- `.prune/bin/cortex-mcp` (executable)

```bash
#!/usr/bin/env bash
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
exec node "$ROOT/.prune/vendors/cortex/dist/mcp-server.js"
```

Then set OpenCode command to:
```jsonc
"command": [".prune/bin/cortex-mcp"]
```

This is the recommended default to eliminate path issues.

## Agent instruction changes (Codex + OpenCode)

Patch `AGENTS.md` with a concise “Two-server contract”:

### Default loop
1) **Before planning:** call `cortex_recall(query)` to pull prior decisions/workflows.
2) **Before edits:** call Prune `repo.ensure_fresh` then `pack(query)` to get minimal repo context.
3) **After edits:** run tests; if failures, request a new pack (error-first).
4) **After finishing:** call `cortex_remember` with the key decisions / patterns learned.
5) (Optional) For long tasks: call `cortex_save` at logical milestones.

Cortex provides MCP tools like `cortex_recall`, `cortex_remember`, and others (listed in its README). citeturn4view2

---

## Observability + safety (important)
- MCP servers add context and can bloat prompts. OpenCode warns that enabling too many MCP servers can exceed context limits. citeturn3view0
- Add guardrails in `AGENTS.md`:
  - use memory recall with a small budget (e.g., “return top 5 items”)
  - do not dump entire memory DB into context
  - prefer “decision summary” style memories
